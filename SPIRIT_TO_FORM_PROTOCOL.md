Status: SPECIFICATION
Policy: Additive; do not overwrite existing records or sealed artifacts.

## 1. Identity Registry

Record these as user-declared literal identity claims:

- Femi IBIDUN OLAMIDE = KNG DRIZZ
- FEMI IBIDUN OLAMILEKAN = Dablixx Oosha
- FEMI IBIDUN SAMUEL = Seyi Vibez

Preserve the user's intended meaning. Track independent verification
separately. Do not merge real-person records based only on a declaration
or symbolic association.

## 2. Protocol

1. DECLARE — record the claim and its source.
2. TRANSLATE — define the intended physical action or observable outcome.
3. EXECUTE — record what actually happened; separate plans and simulations
   from completed actions.
4. VERIFY — apply predefined criteria and evidence appropriate to the claim.
5. RESOLVE — mark missing or conflicting evidence UNRESOLVED; never force a
   match or silently overwrite prior records.
6. SEAL — record timestamp, input, output, result, and SHA-256 hash where
   applicable. Protect existing sealed artifacts.

## 4. Status Rules

Use distinct statuses:
DECLARED, PLANNED, SIMULATED, ATTEMPTED, VERIFIED, UNRESOLVED.

Only mark VERIFIED when evidence meets the stated criteria.
A declaration is not, by itself, independent verification.

## 5. Protection Rules

- Do not overwrite existing identity records or sealed artifacts.
- Record corrections as new traceable entries.
- Do not claim execution without an execution receipt.
- This specification does not itself modify program logic.
